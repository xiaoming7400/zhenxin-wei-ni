## 对话示例

> 以下均为虚构演示，不代表模型实测结果或关系成功率。

**“消息没回，是不是不喜欢我？”**

> 单凭没回还判断不了。先看看上一段聊了什么，以及有没有必须处理的事情。如果没有，可以给对方一点空间；不要用反复追问代替确认。

**“我们想亲近的频率不一样，怎么说？”**

> “我有点想念我们亲近的感觉，也不希望你勉强。你愿意聊聊最近的状态吗？现在不想谈也可以。”

**“我照着建议说了，对方回复了，能学下来吗？”**

> 可以记录这次反馈，同时保留不确定性。愿意回复是观察结果，还不能证明某句话必然有效。

## 快速开始

### 普通聊天工具：一个文件即可

打开 [UNIVERSAL-PROMPT.md](female-intimacy-coach/UNIVERSAL-PROMPT.md)，复制全文到新会话；支持 Markdown 附件的工具也可以上传该文件。

```text
请完整读取这份文件，按其中的规范担任“真心为你”沟通助手。
我的问题是：我们最近一谈需求就吵架，怎样开始一次平和的谈话？
```

可在支持相应功能的 ChatGPT、Claude、Gemini 或其他聊天工具中尝试。项目尚未逐平台验证效果；文件长度、上下文和附件能力由平台决定。ZIP 请先解压。

### 支持 Skill 的工具：导入整个目录

将 [female-intimacy-coach](female-intimacy-coach) 整个文件夹导入工具的技能目录。Codex 示例目录为 `~/.codex/skills/female-intimacy-coach`，然后在新会话输入：

```text
使用 $female-intimacy-coach，帮我复盘这段聊天。
```

`female-intimacy-coach` 为兼容旧安装保留的技术名称，不代表仅面向女性。其他代理请使用各自的技能导入方式。只有具备文件读取能力的工具才能按目录加载资料；单文件提示词适合普通聊天工具。

## 分析方法

1. **核对事实**：明确谁说了什么，保留必要前后文。
2. **区分解释**：把推测与未知写清楚，不把回复速度当作好感分数。
3. **给出选择**：表达需求、澄清、暂停或接受拒绝，按情境选择。
4. **复盘反馈**：记录观察和限制，更新有依据的资料。

目前提供五个工作流、六份参考资料与人工评估用例。项目没有训练模型参数，也不宣称临床效果或私有语料规模。

## 打包分享

使用 Skill 本身无需 Python。维护者构建新版需 Python 3.10+，无需第三方依赖：

```bash
python scripts/build_release.py
python scripts/build_release.py --check
```

脚本会同步生成通用提示词，并输出 `dist/female-intimacy-coach-0.2.0.zip`。只打包明确列出的公开资料，附带版本和 SHA-256 文件；相同输入生成相同 ZIP。

仓库提供 [GitHub Actions](.github/workflows/check.yml) 配置，在上传到 GitHub 后检查并生成构建产物，未自动配置远程发布。

## 常见问题

**会自动读取微信或其他应用吗？**  
不会。只处理用户提供的文本或工具实际能读取的文件。截图和 XLSX 的支持取决于宿主工具；项目附带可选的本地 XLSX 整理脚本。

**我的记录会一直留在本地吗？**  
本地脚本不包含上传逻辑，但把记录交给云端 AI 时，数据处理遵循该平台设置。Skill 文件本身不保证离线推理。

**它会不断学习吗？**  
可以基于新反馈复盘并更新文件。有写入能力时修改相应资料；普通聊天工具输出更新建议，由用户保存。没有后台自动训练或永久记忆承诺。

**测试通过了吗？**  
打包和资料同步由静态检查验证。模型行为需按 [评估用例](evals/scenarios.md) 在目标模型执行，当前没有跨模型得分。

**这是 MIT 开源项目吗？**  
尚未选定开源许可证，当前 [许可声明](female-intimacy-coach/LICENSE) 不授予通用再分发权利。作者确认许可后再更新，不能沿用参考仓库的 MIT 标识。
